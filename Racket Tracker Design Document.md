# Racket Tracker: Design Document

*Version 1.0 · Design agreed in conversation, October 2026 · Status: approved, not yet implemented*

This document is the single source of truth for the app. It is written so it can be handed to any AI (or developer) together with the app folder and a data export, to continue work without the original conversation.

## 1. Purpose and scope

A personal, single-user tracker for tennis racket stringing and usage, running on an Android phone.

It tracks, per racket (the owner has 2, Babolat Pure Strike, white with bright orange):

- Hours played (overall and per string job and overgrip)
- Stringing setups: string models, tensions, knots, with timestamps and photos
- Overgrip setups: model, hours, notes
- Notes (for example "starting to see fraying") with optional photos

**Non-goals (explicitly decided):** no sync, no accounts, no server, no alerts or thresholds, no hours-per-week stats, no average-hours-per-job stat, no note or last-logged-date on the card, no Material You wallpaper colors, no native APK.

## 2. Platform and delivery

- **Format:** Progressive Web App (PWA), plain HTML/CSS/JavaScript, no build tooling, no frameworks required.
- **Hosting:** Netlify Drop (drag-and-drop a folder at app.netlify.com/drop). The host serves code only; all data stays in the phone's browser storage.
- **Browsers:** primarily Firefox for Android (DuckDuckGo browser also possible). Must not rely on Chrome-only APIs. The File System Access API is unavailable on Android browsers and must not be used.
- **Offline:** fully functional offline after first load, via a service worker.
- **Why not a local file:** `file://` storage is unreliable on Android browsers and cannot be installed. Hosting was chosen to get automatic saving and installability.
- **Why not a JSON file as the live store:** web pages cannot silently overwrite files on Android; every save would create a new download. JSON is used for backup only.
- **Data is tied to the web address.** If the site URL changes, the data must be moved with Export and Import.

### Deliverable folder (drag onto Netlify Drop)

- `index.html`: the whole app (HTML, CSS, JS inline)
- `manifest.webmanifest`: name, colors, icons, display standalone
- `sw.js`: tiny service worker that caches the app shell for offline use
- `icon-192.png`, `icon-512.png` (and a maskable variant): orange rounded square with a white racket head and string grid, generated by Claude; easy to replace
- `DESIGN.md` (this document) and `DATA_SPEC.md` (data format and migration notes) for handing to another AI

Updating the app means dragging the updated folder onto the same Netlify site. The service worker cache name must be bumped on every release so phones pick up the new version.

## 3. Terminology

- **Racket:** a physical racket the user owns.
- **String job:** one stringing of a racket (a setup with a start date and, once replaced, an end date). Only one is *current* per racket.
- **Overgrip job:** one overgrip applied to a racket. Same lifecycle as a string job.
- **Entry:** a log record: hours and/or a note, with a date, belonging to a racket. The timeline is made of entries plus automatically generated events (restring, new overgrip).
- **Current:** the job with no end date.
- **Credited to:** the string job and/or overgrip job that an entry's hours count toward.

## 4. Data model

All data is one JSON document with a `schemaVersion` field. Photos are stored separately (see section 7) and referenced by id.

```json
{
  "schemaVersion": 1,
  "app": "racket-tracker",
  "exportedAt": "2026-10-18T10:00:00Z",
  "rackets": [],
  "stringJobs": [],
  "overgripJobs": [],
  "entries": [],
  "settings": { "lastBackupAt": null }
}
```

### 4.1 Racket

- `id` (string, unique)
- `name` (text, for example "Pure Strike A")
- `model` (text, for example "Babolat Pure Strike"; used for the stock-photo search)
- `notes` (optional text about the frame itself)
- `photoId` (optional, a frame photo)
- `createdAt`, `archivedAt` (null unless removed with history kept)

### 4.2 String job

- `id`, `racketId`
- `mains`: `{ model, tensionKg }`. The model is one free-text field that includes the gauge, for example "Tecnifibre Triax 1.33".
- `crosses`: `{ model, tensionKg }`. Same shape. A "same for both" shortcut copies the mains values.
- `knots`: `2` or `4` (applies to the whole job, not per string)
- `startDate`, `endDate` (null while current)
- `photoId` (optional, the racket facing the camera showing the stringing)
- `notes` (optional)

Tension is in kg and may be decimal (for example 24.5).

### 4.3 Overgrip job

- `id`, `racketId`
- `model` (free text, with autocomplete)
- `startDate`, `endDate` (null while current)
- `photoId` (optional)
- `notes` (optional)

### 4.4 Entry

- `id`, `racketId`
- `date` (ISO date; defaults to today)
- `hours` (decimal such as 6.5, or null for a note-only entry)
- `note` (optional text)
- `photoId` (optional photo attached to the note, for example a close-up of fraying)
- `about`: one of `general`, `strings`, `overgrip`, `frame`
- `stringJobId` (nullable), `overgripJobId` (nullable): what the hours and note are credited to
- `createdAt`, `updatedAt`

**Validity rule:** an entry must have `hours` or `note` (or both).

### 4.5 How credit is assigned

When an entry is created, the app looks up which string job and overgrip job of that racket were active on the entry's date and stores their ids in the entry. This stores the decision, so later restrings do not change history. The user can untick strings or overgrip, or pick a specific past job instead. If no job was active on that date, the ids are null and the hours count only toward the racket total.

There is **no special "hours before tracking" field.** Pre-tracking hours are just an entry with null job ids (for example 120 h, dated before the first job).

### 4.6 Adding past jobs

A past job is a string or overgrip job with real start and end dates. Its total hours are entered as a single number; the app stores this as one entry with `hours` set, dated at the job's end date, and credited to that job. So history and in-app logging combine the same way and the racket total stays a plain sum.

## 5. Derived values (never stored)

- **Racket total hours** = sum of `hours` over all of the racket's entries.
- **Hours on a string job** = sum of `hours` over entries with that `stringJobId`.
- **Hours on an overgrip job** = sum of `hours` over entries with that `overgripJobId`.
- **Days since restring** = today minus the current string job's `startDate`.
- **Comparison stats:** hours per job grouped by string model and tension, across all jobs, computed on demand in the detail view.

Nothing is double counted: strings and overgrips overlap in time, so the racket total is never computed from jobs, only from entries.

## 6. Screens and interactions

### 6.1 Home

One card per racket (the user has 2, so the full current stats fit on the card). Each card shows:

- Racket name and the current stringing photo
- **Total racket hours** (all time)
- **Strings:** mains and crosses model, tension in kg for each, knots, date installed, hours on this job, days since restring
- **Overgrip:** model, hours on it, date applied

The card deliberately does **not** show notes or the date of the last hours logged.

On each card there are two buttons:

- **+** (log hours / add note)
- **Pencil** (edit menu)

Tapping the card anywhere else (outside + and pencil) opens the racket detail view. A global control gives access to Add racket and Settings.

### 6.2 The + sheet (log hours and notes)

A bottom sheet with:

- **Hours** (decimal, optional)
- **Date** (defaults to today)
- **Note** (optional) with an optional **photo** (camera or gallery)
- **About:** General, Strings, Overgrip or Frame (default General)
- **Credit to:** current strings and current overgrip, both ticked by default; can untick either or pick a specific past job

At least one of hours or note is required. A note-only entry (for example "fraying" with a photo) and an hours-only entry are both valid. Notes are always available when logging hours; they are not hidden in the pencil menu.

### 6.3 The pencil menu (racket and setup)

- **Edit racket details** (name, model, frame notes, photo)
- **Restring:** closes the current string job and opens a new one. Fields default to the previous job's values; the photo is prompted (skippable); the previous job keeps its photo as history.
- **New overgrip:** same behavior for overgrips.
- **Correct current strings / overgrip:** edits the current job in place to fix a typo. This is deliberately separate from Restring so fixing a mistake never creates a fake job in the history.
- **Add past job:** old strings or overgrip (setup, start and end dates, total hours, optional photo)
- **Edit past entries:** jumps to the timeline
- **Remove racket:** asks for confirmation and offers to keep the history (archives the racket) or delete everything

### 6.4 Racket detail view (tap the card)

- **Current setup:** larger photo and full strings and overgrip details
- **Timeline:** every entry plus restring and grip-change events, sorted by date, with filter chips **All / Hours / Strings / Overgrip / Notes**. Entry photos show as thumbnails; tapping opens full size.
- **String job history:** each past job with photo, setup, dates and total hours
- **Overgrip history:** same format
- **Comparison:** hours per job by string model and tension

Tapping any entry in the timeline opens it for editing or deleting (hours, date, note, photo, About, credited job). This is also where a past note is corrected.

### 6.5 Add racket

Name and model, then an optional "Add previous jobs" section for old strings and overgrips (setup, dates, total hours, optional photo). Pre-tracking hours can be added as an ordinary hours entry. The same previous-jobs form is available later from the pencil menu.

### 6.6 Settings

- **Export backup** (JSON), with options **with photos** and **without photos**
- **Import backup** (file picker; asks before replacing existing data)
- **Last backed up** date shown
- App version and schema version

## 7. Photos

- Source: camera capture or gallery pick, via a file input. The intended subject is the racket facing the camera directly, to show the stringing.
- Each string job and overgrip job can have a photo; each note can have an optional photo.
- **Stock photo alternative:** a PWA cannot search for images itself. A "Find stock photo" button opens an image search for the racket model in the browser; the user saves an image and picks it from the gallery.
- Photos are resized on the phone to roughly 100 to 200 KB before storing.
- Photos live in **IndexedDB** as separate records keyed by `photoId`, not inside the main JSON, so the main data stays small and fast.
- A job or entry keeps its own photo forever; restring never overwrites the old job's photo.
- Exports can embed photos (base64) or omit them.

## 8. Storage, backup and safety

- **Live store:** IndexedDB in the browser (data JSON and photos). Saved automatically on every change.
- The app requests **persistent storage** (`navigator.storage.persist()`) so the browser does not auto-clear it.
- **Clearing the site data in the browser wipes everything**, so the export is the safety net and the last-backed-up date is shown in Settings.
- Export goes to the Downloads folder or the share sheet; import is a file picker.
- Import validates `app` and `schemaVersion`, runs migrations if the file is older, and refuses files from a newer schema than the app knows.

## 9. Changing the data format later

- Every export and every stored document carries `schemaVersion`.
- On load, the app runs ordered migration functions (`v1 → v2 → v3 …`) until the data reaches the current version.
- Migrations must be pure functions of the data, additive where possible, and tested with an old export.
- To change the format: bump the version, add a migration, update `DATA_SPEC.md`, bump the service worker cache name. An AI can do this given the app folder and a recent export.

## 10. Look and feel

- **Standard Android (Material 3)** style: rounded cards, large touch targets, bottom sheets, floating action feel for the + button.
- **Follows the phone's light and dark setting automatically** (CSS `prefers-color-scheme`).
- **Palette** inspired by the Babolat Pure Strike: white or off-white surfaces with a **bright orange accent** (around #FF6A13). In dark mode: charcoal surfaces with the same orange.
- A fixed accent is used; Material You wallpaper colors are not available to web apps.
- **Autocomplete:** string models (including gauge), tensions and overgrip models suggest values used before, so each is typed once.
- Weights and units: hours are decimals (for example 6.5), tension in kg.
- Mobile-first layout, designed for roughly a 380 px wide screen, with no horizontal scrolling.

## 11. Decisions log

- Session start/end times are not tracked; hours are logged directly (racket + hours, optional date and note).
- Past strings and overgrips are added through Add racket and the pencil menu, not through the + button.
- Restring defaults to the previous setup and prompts for a new photo.
- Racket total comes from entries; there is no separate "hours before tracking" field.
- Gauge is part of the string model text, not a separate field.
- Knots (2 or 4) apply to the whole stringing.
- No alerts, no weekly stats, no averages, no note or last-logged date on the card.
- Hosted on Netlify; Synology and local-file options were considered and set aside.

## 12. Test checklist for the build

- Create a racket, add a past string job with total hours, and confirm the racket total matches.
- Log hours with strings and overgrip credited; confirm both job totals and the racket total rise.
- Log hours dated before any job; confirm they count only toward the racket total.
- Restring: previous values prefilled, old job closed with its photo kept, new job current.
- Correct current strings: no new job created.
- Note-only entry with a photo appears in the timeline; the filter chips work.
- Edit and delete an entry; totals update.
- Export with and without photos; import into a clean browser; data and photos match.
- Works offline after first load, in light and dark mode, in Firefox for Android.
- Installs to the home screen and survives closing and reopening.

## 13. Instructions for another AI picking this up

1. Read this document and `DATA_SPEC.md` first, then the `index.html`.
2. Do not add servers, accounts, sync or alerts; they are out of scope.
3. Keep everything in the single `index.html` unless there is a strong reason to split.
4. Any data change requires a schema version bump, a migration and an updated spec.
5. Always bump the service worker cache name on release.
